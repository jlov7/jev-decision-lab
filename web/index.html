    04 · EXPERIMENTS
    Two questions you can only afford to ask a cheap, fast model
    Ask the same question eight times and see how much the answer moves. Then take away one piece of evidence at a time and see which piece was carrying the judgment. Each experiment costs a fraction of a cent and finishes in about a second. Every call is a stored receipt.
    Stability probe
    Send this case 6 times at once. For every answer you get the lowest, middle and highest value seen. A wide bar means the model was not sure; a narrow bar means it said the same thing every time.
    No probe yet.
    Evidence ablation
    Run the case as written, then once more for each evidence excerpt with that excerpt removed. The row that moves the most tells you which piece of evidence the judgment was leaning on. Movement smaller than the model's own call-to-call wobble is marked as noise.
    No ablation yet.
    

    


    A model garden
    is a set of jobs.
    Select capabilities by workload and constraints, not by collecting model brands. This worksheet makes no model calls.
    No recommendation yet
    Choose a task and inspect the role and its required controls.
    What belongs outside every model
    Identity, permissions, source access, deterministic calculations, budgets, event records, independent outcome checks and rollback. A cheaper model cannot waive a data boundary; a stronger model cannot grant authority.
    Experiments are not mandatory inventory
    A company-specific model needs useful training rights, repeat volume and a measured advantage. A world-model experiment needs a state/action problem and a grounded transfer test. Neither belongs in every enterprise by default.
    

    Was the direction
    visible before launch?
    Inspect scientific antecedents and company-specific signals. This is a retrospective chronology, not evidence that your tracker ingested them.
    Three separate audit questions
    Was a public source available? Did the acquisition pipeline capture and parse it? Did synthesis turn it into a useful watch or decision? Only the first can be partly reconstructed from this source pack. The other two need run logs and retained artifacts.
    

    A judgment engine.
    Not a truth engine.
    A writer composes the reply. A dispatcher fills a decision sheet. Your software decides what may happen next.
    Choice
    Select from declared options and inspect their probabilities. A narrow lead is not strong evidence.
    operations 0.62
    procurement 0.33
    quality 0.04
    other 0.01
    Score
    Evaluate ordered descriptions. The mean is a probability-weighted level index; it can conceal a critical tail.
    P(limited) = 0.50
    P(critical) = 0.50
    Noul
    Estimate the probability of yes. A value of 0.5 means uncertainty about a proposition, not medium severity.
    P(sufficient evidence) = 0.45
    Three promises that must stay separate
    Valid shape means the result follows a schema. Calibrated judgment means probability estimates match outcomes across a relevant population. Authorized, accepted work means separate controls and outcome checks passed. None implies the next.
    The confident-wrong teaching case
    Run S04 in Supplier disruption. Its authored replay sends a quality issue to operations with a 0.98 top probability. The label intentionally disagrees. Default policy still follows the owner head; switch to Hold on issue/owner disagreement and replay the policy with zero new model calls. This is not a measured Jev failure; it demonstrates why confidence cannot validate itself. Compare also offers a keyword-rules arm so a delay-word trap (S02) sits beside the model instead of being imagined.
    What an enterprise evaluation needs
    Independently labeled held-out cases, shifted and adversarial slices, matched information, tuned conventional alternatives, end-to-end cost, error severity and review capacity. A synthetic replay score is not a product score. Live evaluation is an explicit terminal command; no live competitor results are bundled.

    Connect your Jev account
    Two steps. Nothing leaves your computer until you tick a consent box and run something.
    1. Get a key. Open the TypeSafe console, go to Settings → API keys, create one, and copy it. Check your credits there too. Open TypeSafe console ↗
    2. Paste it here.
    Where does my key go?
    To this app's own server on your machine (127.0.0.1) and no further. It is held in that process's memory, never written to disk, never put in a log, a URL or a page, and never shown again: you only see its last four characters. Close the server, or click Forget, and it is gone. Every live call still needs you to tick consent first.
    Prefer to keep the key out of the browser?
    Start the server from a terminal with the key held only in that shell. The first command waits for the key without echoing it.
    read -s TYPESAFE_API_KEY
export TYPESAFE_API_KEY JEV_ALLOW_LIVE=1
uv run jev-lab
    This app never reads a .env file. When a terminal key is present, the paste box above is disabled.
    Optional: Claude baseline for Compare
    read -s ANTHROPIC_API_KEY
export ANTHROPIC_API_KEY
uv sync --extra compare
uv run jev-lab
    Attempts are capped per server process: JEV_MAX_LIVE_CALLS (default 20) and JEV_MAX_COMPARE_CALLS (default 40). A full burst or compare on 12 cases uses 12 of each.
    Never put a key in a prompt, a screenshot or a repository. Personal-device access is not approval to send work data.
